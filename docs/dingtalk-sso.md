# 钉钉登录、通讯录同步与本机验证

钉钉是首个企业登录平台。业务身份仍使用本系统 `users.uid`，外部身份存入
`external_identities(provider, tenant_id, subject_id, user_uid, provider_user_id)`。
账号密码登录和现有客户端会话保存机制继续使用，企业微信、飞书后续复用身份表和
通讯录适配器的 `DirectoryRoster` 返回契约。

网关已于 2026-10-10 发布，运行代码提交 `83e6c8844f`，分支 `feat/sso-gateway-release`，
基于此前线上 0.18.4 网关代码合入。
桌面客户端仍在 `feat/dingtalk-login-sso` 本机测试，尚未发版。
本页描述已实现行为及启用步骤，未来 OIDC、TinyDisk 看板托管见 `TODO.md`。

## 启用配置与迁移

1. 使用钉钉**企业内部应用**，登记网关回调：
   `https://<网关域名>/admin/user/dingtalk/callback`。
   本机开发允许相同路径的 `http://127.0.0.1:<端口>` 回调；生产必须 HTTPS。
2. 权限管理开通下列读权限，并核对通讯录授权范围：

   | 权限 | 用途 |
   |---|---|
   | `Contact.User.Read` | 读取本人资料和 Union ID |
   | `qyapi_get_member` | 根据 Union ID 核验本企业内部成员 |
   | `qyapi_get_department_list` | 遍历部门树 |
   | `qyapi_get_department_member` | 部门成员的全部分页 |

   登录通过不代表全量同步权限齐备。只有根部门在授权范围内、所有部门与分页成功，
   才视为完整企业快照。应用正式发布和目标员工可见性需在上线时单独验证。
3. **先运行迁移，再部署新网关**。按仓库的 `scripts/migrate.py` 执行：
   `2026-10-10-external-identities.sql`，随后
   `2026-10-10-sso-directory-sync.sql`。后者新增账号类型、初始改密标记、名册快照、
   操作审计及企业成员唯一索引；文件名已保证迁移顺序。
   部署前应检查既有外部绑定是否存在重复成员 ID。
4. 配置网关 `DINGTALK_CLIENT_ID`、`DINGTALK_CLIENT_SECRET`、`DINGTALK_CORP_ID`、
   `DINGTALK_REDIRECT_URI`。Corp ID 来自授权码交换响应的 `corpId`，不同于 Client ID。
   Secret 仅留服务端，不能放入客户端或 Git。Redis 需支持 `GETDEL`（6.2+）。

参考：[钉钉网页登录教程](https://open.dingtalk.com/document/orgapp/tutorial-obtaining-user-personal-information)、
[部门列表](https://open.dingtalk.com/document/orgapp-server/obtain-the-department-list-v2)、
[部门用户详情](https://open.dingtalk.com/document/orgapp-server/queries-the-complete-information-of-a-department-user)。

## 管理员同步与确认

“用户与角色”页的同步按钮要求 `user:edit`，后端继续校验权限和角色级别。
`POST /admin/account/directory/preview` 只读拉取并保存快照，显示完整性、时间、范围、
上次完整同步时间，以及已绑定、候选、重名、新成员、缺席、标识冲突和外部账号。
姓名只提供候选，所有绑定均由管理员明确选定 UID；不会自动改已有账号的角色或部门。

确认使用 `POST /admin/account/directory/apply`，每批最多 100 项。快照必须属于操作者、
企业配置一致、未超过 30 分钟且没有更新的快照。每行独立事务：创建与绑定一同提交，
身份冲突回滚整行；成功结果持久化，重复提交不会再建账号或再次返回密码。
同一快照的行锁和身份表的三个唯一约束共同处理并发冲突。

部门管理可填写经核对的钉钉部门 ID。只有唯一且启用的映射可用于新账号部门候选，
未映射时可以创建未分配部门的普通员工；模型、审计与其他权限继续走原审批流程。
新账号默认普通员工，生成随机密码并仅存哈希。CSV 只包含本次成功创建的账号，
响应 `Cache-Control: no-store`；下载前记录导出审计，下载或关闭后清除前端密码数据。
断网、丢失响应或下载文件后，只能通过管理员重置取得新密码。

密码首次登录生成受限会话，只允许查看本人资料及修改初始密码；改密前不能创建
设备 API Key 或调用 `/v1`。网页转到改密页，桌面端提示设置个人密码并重新登录。
钉钉已经验证的身份会话不需要使用初始密码。

离职处理只作用于同步前已绑定的内部账号。连续两次完整快照缺席，且账号位于
操作者管理范围，才出现禁用选项；仍需人工确认。外部账号、未绑定账号、局部范围、
接口失败和漏页均不能据此禁用。账号状态从数据库即时读取，禁用撤销会话与设备 Key。
离职事件适配、外部人员的完整登录流程和重新入职恢复仍属后续工作。

## 桌面登录交接

桌面端查询网关钉钉配置；只有启用且声明 `auth_flows: ["native_pkce"]` 才显示钉钉主要入口。
旧网关未提供 native 能力时继续用密码登录。交接响应分开返回稳定 `user_id`（本地 UID）
和展示用 `username`，改花名不会改变业务身份。复用既有
`runNativeLogin`：在 `127.0.0.1` 临时端口监听，生成 state 与 PKCE S256，打开系统浏览器。
网关入口为 `/admin/auth/native/authorize`，钉钉回调仍是已登记的网关地址。

钉钉企业与身份校验成功且已绑定后，浏览器只拿到 60 秒、一次性使用的交接码，
访问/刷新令牌不进 URL。客户端携 verifier 调用 `/admin/auth/native/token`；网关再次
校验账号状态与企业配置，然后签发自身令牌。客户端沿用已有设备 Key 签发、加密
保存、刷新、配置同步和退出撤销路径。可以取消等待；迟到结果不应恢复已退出会话。
未绑定身份明确提示联系管理员同步绑定。

这些接口服务当前工作台，并不构成通用 OIDC 身份提供方。后续系统及 TinyDisk
需在统一 UID 的基础上接入标准协议和资源授权。
